# Shady Meadows B&B — SDET Technical Challenge

## How to run

**Karate (API tests)** — requires Java 21 and Maven:
```bash
cd karate
mvn test
```
Report: open `karate/target/karate-reports/karate-summary.html` in the browser.

**Playwright (UI tests)** — requires Node.js:
```bash
cd playwright
npm install
npx playwright test
```
To open the report (optional): `npx playwright show-report`

## Approach

For the API tests I used Karate DSL with Maven and JUnit 5. Each scenario is independent. The booking test checks room availability for tomorrow before creating the booking, and deletes it afterwards so the test can run multiple times without issues.

For the UI tests I used Playwright with TypeScript, using user-facing locators (`getByRole`, `getByLabel`) as recommended in the challenge tips. The bonus test scrapes room details from the public homepage and compares them against the admin panel.

## Bugs found

1. The challenge specifies endpoints `/branding/`, `/room/` and `/booking/` but these return 404 on the current site. The actual working paths are `/api/branding/`, `/api/room/` and `/api/booking/`.

2. The challenge says to verify "Book this room" buttons but the site shows "Book now" links. The test was written against what the site actually renders.

3. When trying to locate the Contact form using `getByRole('form')`, Playwright could not find it. The workaround was to verify the form heading and the Submit button instead.

## CI/CD

GitHub Actions runs both test suites on every push to `main`. Reports are uploaded as artifacts with 30-day retention.

The Playwright workflow was auto-generated by `npm init playwright@latest`. The Karate job was simplified and adapted from the official example at https://github.com/karatelabs/karate-todo/blob/main/.github/workflows/cicd.yml.
